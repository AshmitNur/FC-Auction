# PRD: FC 26 Custom LAN Tournament Fixture + Player Auction App

## 1. Product Overview

The app will manage a **12-person FC 26 LAN tournament** with a built-in **player auction system**. Each tournament participant acts as a team owner, joins an auction, buys FC 26 players using a fixed coin budget, builds a squad, and then plays fixtures generated by the app.

For the auction pool, **“above 80 rating” means OVR 81+**. The app should therefore include all official EA Sports FC 26 players rated **81 overall or higher**.

---

## 3. Recommended Fixture Format

### Default Format: 2 Groups + Knockout

For a 12-player LAN tournament, the recommended structure is:

| Group A | Group B |
|---|---|
| 6 participants | 6 participants |

Each participant plays every other participant in their group once.

### Match Count

| Stage | Matches |
|---|---:|
| Group A | 15 |
| Group B | 15 |
| Quarter-finals | 4 |
| Semi-finals | 2 |
| Final | 1 |
| Third-place match | Optional |

Total matches: **37 or 38**, depending on whether a third-place match is enabled.

## 6. Auction System

## 6.1 Auction Pool

The app must include:

```text
All official EA Sports FC 26 players with OVR >= 81
```

This means only players rated:

```text
81, 82, 83, 84, 85, 86, 87, 88, 89, 90, 91+
```

Players rated exactly **80** should not be included if the rule is strictly **above 80**.

---

## 6.2 Budget Rules

Each participant starts with:

```text
2,000,000,000 coins
```

Minimum opening bid:

```text
10,000,000 coins
```

Minimum bid increment:

```text
10,000,000 coins
```

### Valid Bid Examples

| Bid Round | Valid Bid |
|---|---:|
| Opening bid | 10,000,000 |
| Next bid | 20,000,000 |
| Next bid | 30,000,000 |
| Next bid | 40,000,000 |
| Next bid | 50,000,000 |

### Invalid Bid Examples

| Bid | Reason |
|---:|---|
| 5,000,000 | Below minimum opening bid |
| 15,000,000 | Not in 10 million increment |
| 23,000,000 | Not in 10 million increment |
| 2,100,000,000 | Exceeds participant budget |

## 6.3 Auction Flow

### Step 1: Auction Starts

The admin starts the auction session.

The app displays:

| Field | Example |
|---|---|
| Current player | Kylian Mbappé |
| Rating | 91 |
| Position | ST |
| Club | Real Madrid |
| Base price | 10,000,000 |
| Current highest bid | 0 |
| Highest bidder | None |

---

### Step 2: Player Nomination

The app should support two nomination modes:

#### Option A: Admin Nominates Player

Admin manually selects the next footballer for auction.

#### Option B: Random Nomination

The app randomly selects one unsold player from the 81+ player pool.

---

### Step 3: Bidding

Participants place bids in real time.

A bid is valid only if:

1. Bid is at least **10,000,000 coins**.
2. Bid is higher than the current highest bid.
3. Bid follows the minimum increment rule.
4. Participant has enough remaining budget.
5. Participant has not reached the maximum squad size.
6. Player has not already been sold.

---

### Step 4: Timer

Recommended timer:

```text
30 seconds per player
```

Late-bid rule:

```text
If a bid is placed in the final 5 seconds, extend the timer by 5 seconds.
```

This prevents unfair last-second bidding.

---

### Step 5: Player Sold

When the timer ends, the player is sold to the highest bidder.

The app updates:

| Item | Update |
|---|---|
| Participant squad | Add player |
| Participant budget | Deduct winning bid |
| Player status | Mark as sold |
| Auction log | Save transaction |
| Auction screen | Move to next player |

---

## 6.4 Mandatory Auction Rules

1. Each participant starts with **2 billion coins**.
2. Minimum opening bid is **10 million coins**.
3. Minimum increment is **10 million coins**.
4. A participant cannot bid more than their remaining budget.
5. A sold player cannot be auctioned again.
6. A participant cannot buy duplicate players.
7. Admin can pause, resume, skip, or restart an auction.
8. Admin can undo the last sale if a mistake happens.
9. Every auction action must be saved in an auction history log.
10. The auction should continue until the admin ends it or all squad requirements are fulfilled.

## 15. Validation Rules

## 15.1 Bid Validation

A bid should be rejected if:

```text
bid_amount < 10,000,000
```

or

```text
bid_amount % 10,000,000 != 0
```

or

```text
bid_amount > participant.remaining_budget
```

or

```text
player.status == "sold"
```

or

```text
participant.squad_size >= maximum_squad_size
```

---

## 15.2 Result Validation

A match result should be rejected if:

1. Fixture does not exist.
2. Match is already completed and locked.
3. Score fields are empty.
4. Knockout winner is not selected after a draw.
5. Admin does not have permission.

## 16. Success Criteria

The app is successful if:

1. All 12 participants can join the tournament.
2. Every participant receives exactly **2 billion coins**.
3. The auction only allows players rated **81+**.
4. No participant can overspend.
5. Every sold player is assigned to only one participant.
6. Fixtures are generated correctly.
7. Points table updates automatically.
8. Knockout bracket updates automatically.
9. Admin can complete the full tournament without spreadsheets.
10. The app works smoothly on a local LAN connection.
